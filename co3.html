CO3 Unit III · DGPS and Data Processing

Differential GPS (DGPS)

Course Outcome

CO3: Know the use of DGPS and its applications and advantages.

Introduction

Standalone GPS position fixes carry several metres of error from satellite clock, orbit, and atmospheric effects. Differential GPS (DGPS) is a technique that removes most of these errors by comparing observations from two receivers, boosting positioning accuracy from several metres down to sub-metre or even centimetre level — essential for engineering-grade surveying.

Differential Correction Principle

DGPS uses a base station set up on a point whose exact coordinates are already known, and one or more rover receivers moving over the area to be surveyed. Because both receivers see largely the same satellites through nearly the same atmosphere, most error sources (satellite clock, ephemeris, ionospheric and tropospheric delay) affect them almost identically.

The base station computes the difference between its known position and the position GPS alone gives it — this difference is the correction. That correction is transmitted to the rover and applied to the rover's own GPS solution, cancelling out the shared error.

DGPS Working — Real-Time vs Post-Processed

  • Real-time DGPS: The base station broadcasts corrections continuously (e.g. via RTCM radio link, mobile data, or satellite) and the rover applies them instantly, giving corrected coordinates in the field immediately.
  • Post-processed DGPS: Both base and rover simply log raw data; corrections are computed and applied afterwards in office software. Useful when no real-time communication link is available.

Control Station Set-up

Setting up a reliable base/control station is critical to DGPS accuracy:

  1. Choose a stable, open-sky location free from overhead obstructions and multipath sources (buildings, metal structures, water bodies).
  2. Occupy a point with known or precisely surveyed coordinates — ideally an existing benchmark or a point observed for an extended session.
  3. Level and centre the receiver antenna accurately, and record antenna height.
  4. Log data continuously for the duration of the rover's survey session so corrections are available throughout.

DGPS Data Application & Processing

In post-processed DGPS (and in every control survey) the raw data from all receivers is brought to the office and processed in this order:

  1. Import and check: load raw or RINEX files from every receiver; check station names, antenna types and antenna heights against the field book. A wrong antenna height is the most common blunder.
  2. Get reference data: add the known control coordinates, and if needed the data of the nearest CORS station and precise satellite orbits.
  3. Baseline processing: for every pair of receivers that observed together, the software computes the baseline: the 3D vector (ΔX, ΔY, ΔZ) between them. It uses the difference between the two receivers' data (differencing), which cancels clock, orbit and most atmospheric errors.
  4. Check each baseline: a carrier-phase solution should be fixed (the whole number of wavelengths found), not float. Float or poor baselines are removed or re-observed.
  5. Loop closure check: test closed loops of baselines (next section).
  6. Network adjustment: hold the known control points fixed and adjust all baselines together by least squares, giving final coordinates with their accuracy.
  7. Transform and report: convert to the project coordinate system (for example UTM zone 44N) and heights above mean sea level; prepare the report and export to CAD/GIS.

Applications of DGPS data: establishing and densifying control networks, ground control points for drone mapping, topographic and cadastral surveys, road and canal alignment, setting out with RTK, hydrographic survey and dredging, precision agriculture and machine guidance, and monitoring of structures and land movement.

Loop Closure Technique

In a GPS control survey, baselines form closed loops (triangles or polygons) between stations. Because a loop starts and ends at the same point, the baseline vectors around it must add up to zero:

ΣΔX = 0,   ΣΔY = 0,   ΣΔZ = 0

In practice the sums are small but not zero. This is the loop misclosure:

Misclosure = √(ΣΔX² + ΣΔY² + ΣΔZ²),   and   misclosure in ppm = (misclosure ÷ loop length) × 106

If the misclosure is within the limit set by the survey specification, the baselines are accepted and adjusted. If not, the bad baseline is found (it shows up in every loop it belongs to) and is re-processed or re-observed. Loops are built from baselines of different sessions; a loop made from one session only always closes and proves nothing.

Misclosure = √(0.014² + 0.011² + 0.008²) = 0.0195 m ≈ 19.5 mm. Relative misclosure = 0.0195 ÷ 4197.071 × 106 ≈ 4.6 ppm (about 1 in 215 000). Compare this with the limit in the project specification; if it is within the limit, the loop is accepted.

Note: the same idea is used in a closed total-station traverse (CO4): the traverse returns to a known point, and the closing error is distributed, for example by the Bowditch rule. In GPS the check is done on 3D baseline vectors instead of angles and distances.

DGPS Today: CORS and RTK

  • DGPS vs RTK: classic DGPS corrects code measurements and gives sub-metre to metre accuracy. RTK uses carrier-phase corrections and gives 1–3 cm in real time. Both use the same base-and-rover idea.
  • CORS: a Continuously Operating Reference Station is a permanent base station that records all the time. With a CORS network the surveyor needs only a rover. Survey of India's CORS network gives real-time RTK positioning with an accuracy of about ±3 cm; the Surveyor General reported 1,145 stations in February 2026.
  • Network RTK: the corrections of several CORS stations are combined, so accuracy stays good even far from any single station.

Applications

DGPS is widely used for topographic and cadastral surveys, precision agriculture, marine navigation and dredging, and as the reference correction source for RTK GPS surveying.
